01What is a metadata-driven data quality platform?+
Resume evidence

Understand it

Metadata is configuration describing data. Instead of adding new hard-coded checks for every table, the engine reads rules and applies reusable validation functions.

Simple example

A rules table might contain dataset=orders, column=amount, rule=non_negative, severity=error. Another row checks that order_id is present.

Generic example · prerequisites in the answer
rules = [{'column': 'amount', 'min': 0}]
rows = [{'amount': 10}, {'amount': -2}]
failed = [r for r in rows if r['amount'] < rules[0]['min']]
print(failed)
Expected result
[{'amount': -2}]

Short interview answer

I worked on a configurable data quality platform using Python, PySpark, and PostgreSQL. Rules were managed as metadata so onboarding a dataset needed less custom validation code.

Detailed explanation

Generic mechanism: load active rules from PostgreSQL; validate rule types and columns; read the dataset; apply Spark expressions; record checked, passed, and failed counts; retain reject reasons; enforce the configured publication gate. Separate configuration from execution and results. A rule identifier and run identifier make failures traceable. This is a reconstruction of the design pattern, not recovered employer source code.

Likely follow-up

Why PostgreSQL? It provides structured, queryable configuration and validation results. What if a rule references a missing column? Fail configuration validation with a clear error.

Common mistake

Do not silently skip invalid rules or collect all failed rows to the Spark driver.
